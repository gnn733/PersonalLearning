# 建议学习顺序

[返回分类导航](README.md)

适用情况：研一，JavaWeb 刚开始，MySQL 有基础，Python 有基础并接触过 LangChain，每周约 30 小时。以下按完成标准推进，时间分配可以根据课程、科研与项目难点调整。

## 每周时间分配参考

| 用途 | 每周时间 | 主要内容 |
| --- | ---: | --- |
| Java 与后端主线 | 18 小时 | JavaWeb、Spring Boot、MyBatis 与实际编码 |
| Python 与 Agent 项目 | 9 小时 | ReAct、RAG、工具封装、调试 |
| 复习与总结 | 3 小时 | JavaGuide 对照复习、整理报错与调用流程 |

## 阶段 1：看懂请求如何流动

### 学什么

- HTML 表单、输入框、按钮。
- JavaScript 基本对象、事件与 fetch。
- HTTP、JSON、请求与响应。
- Maven、Tomcat、Servlet。
- JDBC 与数据库连接。

### 做什么

输入关键词 → 点击查询 → Java 查询 MySQL → 页面显示结果。

### 完成标准

能说明请求地址、参数、数据库查询和返回内容；能用浏览器 Network 查看请求，用后端日志查错误。

资料：[Java 分类](java/README.md)。

## 阶段 2：同时建立 Agent 的整体理解

### 学什么

- Hello-Agents 第一章与第四章 ReAct 部分。
- 模型请求调用工具，程序执行工具，再返回结果的流程。
- 复习自己已经写过的文档检索代码。

### 做什么

先测试检索函数，再把它封装成工具接给 Agent。

### 完成标准

终端提问后，能看到检索工具调用及结果，输出有来源的答案。能解释工具为什么被调用，以及答案的依据在哪里。

资料：[Agent 与 RAG 分类](agent-rag/README.md)。

## 阶段 3：完成 Java 基础项目

### 学什么

- Spring Boot、Controller/Service/Mapper 分工。
- MyBatis、参数校验、异常处理、日志。
- 会话管理与资源归属检查。

### 做什么

完成学习笔记管理系统，逐步加入登录、分页和条件查询。

### 完成标准

能独立修改功能、调整表结构、定位常见错误。开源项目可以作为参照，自己的业务逻辑应能讲清楚。

资料：[Java 项目](projects/README.md)。

## 阶段 4：把 Agent 开放成服务

### 学什么

- FastAPI 的路由、请求体、Pydantic 校验、错误响应。
- 基础 async/await，以及同步阻塞调用的问题。
- 会话历史保存、超时、日志、流式输出的基础。
- 环境变量、依赖管理、Linux 与 Docker 基础。

### 做什么

把终端 Agent 函数接到 /chat 接口，逐步保存对话并增加简单页面。

### 完成标准

另一程序能调用接口；不同会话历史能区分；模型或工具失败时能返回清晰错误；服务可以按说明在另一环境启动。

## 阶段 5：按项目问题补深度

| 遇到的问题 | 再学习什么 |
| --- | --- |
| SQL 查询慢 | 索引、EXPLAIN、慢查询 |
| 数据重复读取或需要简单限流 | Redis 与对应数据结构 |
| 文件处理时间长 | 后台任务、任务状态；需要持久与独立执行时再考虑消息队列 |
| 工具经常失败 | 超时、有限重试、幂等性 |
| Agent 结果不稳定 | 固定测试集、检索效果分析、提示与工具描述调整 |
| 多轮对话内容越来越多 | 上下文管理、摘要与状态持久化 |
| 希望用 Java 做 Agent | Spring AI Alibaba 的简单工具示例 |

## Agent 后续专项路线

Java 与 Agent 两条线可以并行。Agent 的后续顺序建议为：基础 RAG 与小型评估 → LangGraph 状态/节点/边 → 工具循环 → 有限改写的 Agentic RAG → 记忆/流式/人工确认 → 接口与部署 → 按需 MCP/子图/多 Agent。

- [逐阶段任务与完成标准](agent-rag/after-rag-roadmap.md)
- [LangGraph 具体学习顺序](agent-rag/langgraph-study-guide.md)
- [新增资料及版本注意](agent-rag/advanced-resources.md)

每周约 9 小时 Agent 学习时间，可以分为约 3 小时教程、5 小时编码调试、1 小时复盘；按完成标准推进，遇到科研或课程安排时调整。

## 每完成一个功能，记录四件事

1. 用户输入了什么？
2. 数据经过哪些函数、服务和数据库？
3. 成功结果是什么，失败如何处理？
4. 自己修改了什么，怎样验证？

这四个问题也能帮助准备实习面试中的项目介绍。
